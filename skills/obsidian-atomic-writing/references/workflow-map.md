# 寫作流程圖：4 層 × 7 節點

來源：〈用 Claude 做自己的寫作工具後，我更理解寫作的價值〉資訊圖（@chihua.wang.3）。
每一層由左至右推進；縱向箭頭把關鍵節點串到下一層；第四層的成果回流到前三層，形成循環。

## ① 問題或觀察（工具層）：從需求出發，定義寫作的起點
Claude（AI 作為協作夥伴）→ 寫作（把思考化為文字）→ 工具（讓流程更順暢）→ 需求（釐清寫作目標）→ Workflow（串連個人工作流）→ HTML（支援彈性輸出）→ 編輯器（提供書寫介面）

## ② 概念架構（結構層）：建立寫作系統的結構與連結
Atomic Essay（以小單位組合內容）→ 核心觀點（形成文章主軸）→ 小標題（組織段落結構）→ 正文（展開論述與分析）→ 結論（收束並回應問題）→ 四色（區分內容類型）→ 筆記（記錄想法與素材）

## ③ 實踐與回饋（思考層）：從內容到成品，持續迭代優化
資料結構（整理與連結資訊）→ 介面（降低操作門檻）→ 摘要（快速掌握重點）→ 理解（建立個人詮釋）→ 驗證（檢查並修正觀點）→ 思考（深入探索問題）→ 例子（用實例具體化）

## ④ 長期能力（產出層）：內化為可持續的寫作力
疑問（提出關鍵問題）→ 圖片（補充視覺與脈絡）→ 匯出（轉換為多種格式）→ 保存（長期留存與管理）→ 創作（形塑獨特觀點）→ 文章（完成可公開的作品）→ 能力（持續提升寫作力）

## 縱向路徑
- 單元化線：Claude → Atomic Essay → 資料結構 → 疑問
- 思考主軸：需求 → 正文 → 理解；驗證 → 創作
- 格式線：HTML → 四色 → 思考
- 編輯器 → 筆記

## 本技能如何對應
| 技能動作 | 對應節點 |
|---|---|
| 模式 A 記錄 | 筆記、資料結構、摘要、疑問、四色 |
| 模式 B 寫作 | 需求、Atomic Essay、核心觀點、小標題、正文、結論、理解、驗證、思考、例子、創作、文章 |
| 模式 C 保存 | 匯出、保存、Workflow |
| 驗證清單、下一步 | 回流箭頭：每次產出都回頭強化下一輪 |

## 綜合觀點
從工具使用到思考升級，讓寫作成為長期可累積的能力。AI 讓編輯器、排版與匯出變得容易，卻沒有替人完成思考；當工具可以從自己的 Workflow 長出來，真正值得鍛鍊的反而是理解、驗證與寫成自己的觀點。
